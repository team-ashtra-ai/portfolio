# Layout System

This site will not reuse the same layout structure as the previous sites.

This site will not use the same hero-card-grid-FAQ-CTA rhythm unless redesigned completely.

## Layout Difference Plan

| Layer | Rule |
| --- | --- |
| Overall layout archetype | Legal platform workflow |
| Page width system | uses --container-sm/md/lg/xl/fluid with per-site values in css/styles.css |
| Container system | Legal platform workflow containers with measured density |
| Section rhythm | paced around Workflow tab reveal and varied section composition |
| Grid/column structure | Workflow document cards and Workflow document cards control grid emphasis |
| Asymmetry rules | each page rotates at least one asymmetric, full-bleed, sticky, or report-led section |
| Full-bleed rules | allowed for Blue legal software hero, gallery, proof, and CTA moments only |
| Boxed/split rules | boxed surfaces use Legal SaaS with calm blue authority, soft cream pages, and product proof; split sections must not repeat image-left/text-right by default |
| Sidebar/sticky rules | use only on resource, proof, contact, pricing, or utility pages when it supports conversion |
| Overlap/negative space | controlled by measured spacing and not copied from avoid-list sites |
| Visual hierarchy | Georgia display with Verdana body and Inter accent labels plus clear primary/secondary CTA hierarchy |
| Page density | measured |

## Static Authorship Pass

This site folder is now treated as the editable static source for `CivicLex`. The duplicate secondary header route strip was removed from the static HTML, and the footer markup/CSS was rewritten directly in the site files using the `product` footer pattern for the `Clio` inspiration direction. Future edits should happen in this site folder rather than regenerating shared templates.

## Asset Handoff Documentation

The public site no longer exposes an asset-system HTML route. Asset inventories remain in the docs folder and local asset tree for QA and handoff; public navigation uses only the 10 core pages and 7 universal utility pages.

## Portfolio Section Component Pass - 2026-05-11

CivicLex now treats every main-body section as a static, WordPress-ready component with a component ID, section type, layout variation, pattern family, mobile stacking rule, and editable field map. The pass keeps the Clio inspiration as a principle reference only while using original local markup, CSS, JS, and assets. Repeated section names are deliberately varied so Hero, Services, Process, Results, FAQ, Contact, and CTA patterns do not collapse into one shared layout.
